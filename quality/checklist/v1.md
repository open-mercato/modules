# OM Quality checklist v1

OM Quality is granted by people only, per published tarball (`dist.integrity`), for 12 months. Every item is pass or fail with a file and a line. A review is stored as `quality/reviews/<locpath>/<version>.yml` and needs two reviewers from the core team.

Preconditions: the version is Verified, the entry is Claimed, provenance is `verified` or a GitHub tag equals the version, and the license is explicit (`UNLICENSED` only with a review agreement).

| ID     | Check                                                                                                  |
| ------ | ------------------------------------------------------------------------------------------------------ |
| OMQ-01 | Tenant isolation: queries are scoped by `tenant_id` and `organization_id`.                             |
| OMQ-02 | Every route and page declares `requireFeatures`; public routes are justified.                          |
| OMQ-03 | `defaultRoleFeatures` in `setup.ts` are proportionate.                                                 |
| OMQ-04 | Migrations are additive, tables use the module prefix, no DDL on core tables.                          |
| OMQ-05 | Event IDs follow `module.entity.action`.                                                               |
| OMQ-06 | Observed hosts equal declared hosts; no `eval`, `new Function` or `child_process`.                     |
| OMQ-07 | Secrets go through the Open Mercato credentials mechanism; environment variables are documented.       |
| OMQ-08 | Dependencies have no install scripts and no known vulnerabilities; the release ships a CycloneDX SBOM. |
| OMQ-09 | The repository has tests and green CI.                                                                 |
| OMQ-10 | UI uses `@open-mercato/ui`; i18n follows the convention.                                               |
| OMQ-11 | README covers install and configuration; the package ships `AGENTS.md`.                                |
| OMQ-12 | Peer dependencies are ranges, or a pin is justified.                                                   |

Review time can be paid for. The result cannot.

Revocation: automatic when `integrity` changes (a new version does not inherit the review), when Verified is lost for more than 14 days, or when a high or critical advisory stays unfixed for 14 days. Manual revocations are listed in `quality/revocations.yml`.

A patch release with an empty anatomy diff and unchanged Hygiene can be signed by one reviewer after reading the diff.
