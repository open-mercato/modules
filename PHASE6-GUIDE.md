## HOW TO BUILD A PAGE

(1) Content: www/content/pages/<slug>.yaml, typed blocks only (a `copy` block fails the build). EVERY visible word lives in the YAML, never typed in a component (icons, decorative SVG and structural markup belong in components). Take seo.title / seo.description / ogImage and `webflowId` from the importer's draft, which is at /home/wojtek/cezar/projects/modules/.ai/cezar/tmp/1b1e8cf1-5884-4808-95e6-1c5c41db32f8/import/www/content/pages/<slug>.yaml (if you cannot read that path, take them from the live page head). Long dashes U+2014 and U+2013 become `-` (spec A5; `yarn check` fails on them). A hand-typed plugin or module count ("50+ plugins", "50+ modules") becomes the token `{moduleCount}` (owner decision: the real count from the catalog's data, not "50+"); a star count becomes `{githubStars}`. (2) Markup: one component per live section design, www/src/components/blocks/<slug>-<name>.astro, named by the block's `layout`; reproduce the live section's markup and Webflow classes; wrap with Wrap.astro (tone main/dark/white) or the page's own wrapper as live has it. Props: `BlockProps<'<type>'>`; fill tokens with fillCounts from lib/core/www-tokens.ts; render Markdown with the helpers above. Pick the block type that fits the content (hero, features with items, carousel, video, stats, team, quote, steps, faq, cta, prose, logos, list); do not change the schema. If something truly cannot be expressed, report the exact schema change you need instead of editing lib/. (3) Page CSS: the live page's embedded <style> code goes to www/src/styles/webflow/pages/<slug>.css (PageView loads it automatically; the body has class `wf-<slug>`, so a live `html[data-wf-page="..."]` selector becomes `body.wf-<slug>`), with a header comment like pages/team.css (origin URL and date). A Webflow rule missing from site.css goes to your page CSS, marked as such. (4) Legacy embeds whose source is unknown (spec Q4; /crm's 12 compiled Astro embeds, their data-astro-cid-* classes kept) are ported as they are into www/src/components/legacy/<slug>-<name>.astro and placed with a `type: legacy` block whose `note` says what it is; their scripts become `<script>` blocks in the component (no jQuery, no Webflow runtime, no new dependency). (5) Images and files (D5): download every image, poster and file the section shows into www/public/media/pages/<webflowFileId>-<name lowercased, non [a-z0-9.-] as ->.<ext> (the importer's naming; some are already there); never hotlink cdn.prod.website-files.com or i.ytimg.com. (6) JSON-LD: set `jsonLd.type` to the live page's type (home WebPage, product SoftwareApplication, architecture TechArticle, about AboutPage, careers AboutPage, contact ContactPage, how-to-contribute HowTo, learn-ai-engineering HowTo, agencies/partners/enterprise-level-support WebPage, agent-orchestrator and crm none); a live FAQPage whose questions are not shown on the page goes to `jsonLd.faq` (copy the questions and answers from the live head script, dashes as `-`). (7) CTA tracking: add data-cta-placement / data-cta-action (lib/core/cta.ts ctaAttrs) ONLY where the live tracking script has a rule for that element; the script's rules are: `.om-hero-actions` a -> ['hero', sandbox link ? 'build_in_sandbox' : github repo link ? 'clone_repo' : slug(text)]; `.om-release-label` -> ['hero','release']; `.omr-developer-command` -> ['sandbox','copy_clone_command']; inside `.omr-sandbox` -> ['sandbox', sandbox ? 'build_in_sandbox' : slug(text)]; inside `.cta_component,.om-final-actions` -> ['final', ...] (the shared closing CTA already has it); `.omr-play` -> [inside .omr-academy ? 'academy' : 'stories','play_video'] (aria-label "Play: <title>"); `.omr-academy-link` -> ['academy','explore']; `.case-list_card-link` -> ['cases','open_story']; a link to /case-studies inside `.case-slider_buttons` -> ['cases','view_all']. slug(text) lowercases and turns runs of other characters into `_`; text is `.text-size-small` text, else aria-label, else the element's text. No new event names. (8) The shared closing CTA (www/src/components/site/SiteCta.astro) follows every page; set `siteCta: false` only where live has its own (/crm). The shared header and footer are the catalog's; do not touch them. (9) Gotcha: site/src/styles/base.css sets `list-style: none` on ul/ol[role=list]; where live shows bullets or numbers, leave role="list" out. (10) Links to other main-site pages are site paths (/contact, /agencies), never the live origin.
